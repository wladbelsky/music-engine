Context for Claude Code / Claude when working on this project.

## What it is
An audio-reactive web wallpaper for Wallpaper Engine (WE). A 3D engine (Three.js) on the left, a 2D dashboard on the right.
The engine (piston layouts, a steam mill engine, a turbojet, a brushed DC motor, a marine crosshead diesel or a rocket cluster on a test stand) revs with the music (BPM + loudness), shoots flames on peaks (steam: stoked fire and sparks; jet: afterburner; electric: blue arcs and a commutator flashover; marine: black smoke and relief-valve flames; rocket: plumes), sways/vibrates more with RPM, and stalls after silence.
The dashboard has a tachometer with shift lights, temp and boost gauges, 8 lamps (round lamp + metal plate with screws), an ignition key, a throttle pedal, an odometer (ODO + TRIP drums), and a car radio (now playing via WE media integration).

## Architecture (plain scripts, no build step, no ES modules)
Load order in `index.html`: `three.min.js → audio.js → sim.js → fx.js → engine3d.js → layout.js → piston.js → piston-layouts.js → steam.js → jet.js → electric.js → marine.js → rocket.js → induction.js → dash.js → bg.js → media.js → odometer.js → main.js`.
Each file is an IIFE exporting a class to `window`. `js/core/` knows no engine by name; every engine lives in `js/engines/` and registers itself (`EngineTypes` for behaviour + instruments, `EngineLayouts` for the 3D model; `js/core/layout.js`).
**Adding an engine** = one file in `js/engines/` (`EngineTypes.register({...})` unless it reuses a type, a layout class extending `EngineLayouts.base` with statics `id, kind, title, normCyl, label, turbos, blower`, `EngineLayouts.register(cls)`), a `<script>` line before `induction.js`, `npm run sync:project` (writes the `layout` combo and the `turbos`/`redline` conditions of project.json; `contract.test.js` fails while it's stale), then `npm run baseline` once the user has approved it (so later changes can't quietly alter it). The dev panel's layout options come from the registry.
Favicon (browser tab only): `favicon.svg` (a tachometer with a red zone) + `favicon.png` (32×32 fallback, a headless Chromium screenshot of the SVG; re-render it when the SVG changes).

|---|---|
| `js/core/audio.js` | `AudioAnalyzer.push(arr128, t)`: mono bands, spectral flux, beats (adaptive threshold), BPM (autocorrelation over ~300 frames + log-gaussian prior at 120 + parabolic interpolation, folded into 80–170), `intensity`/`power` (absolute via slow AGC + relative to 20 s EMA + beat density), `silentTime`. `tick(t)` treats "no callbacks" as silence (`silentTime = t - lastPush`). | `js/core/sim.js` | `EngineSim.update(dt, audio, t)`. States: `off → lamptest → cranking → running ⇄ stalling → stalled`. Fields: `rpm, target, throttle, boost, temp, flame, kick, pedal, ignition, pedalIn, warn{}`, event queue `takeEvents()` (`backfire`, `bov`, `smoke`, `start`, `vent`). `pw = max(audio.power, pedal*0.95)` drives flames and temperature. Generic: nothing names an engine. `type()` = `EngineTypes.get(settings.kind)` (unknown → piston); `sim.boost` is the right gauge's channel = max over `type.sim.sources(settings, maxBoost)` (each `{v, rise, fall, target(sim, red), rest?(sim)}`, `rest` = the value outside `running`), rebuilt when kind/turbos/blower change; `maxBoost` → OVERBOOST lamp at 0.93. `type.sim.after(sim, dt, t)` for extra events (steam's `vent`: near the top, 3 s cooldown, `sim._ventT`). `CRANK {time 0.9, rpm 230, wobble 70, rise 20, fire 1500, smoke 1, shake true}` (`fire: null` = carry on from the run-up, `smoke 0` = none, `shake false` = no starter jerk in `Engine3D._sway`) / `STALL {rpm 380, stumble 500, pops}` are overridable per type (`type.sim.crank/stall`: the motor runs up without wobble or pops, the diesel turns over on air for 1.8 s, the rocket chills down 1.6 s). `bov` events only when `turbos > 0`. Types with a fixed `redline` (7000) run the sim on that internal scale (the redline slider is hidden for them), the dash converts. |
| `js/core/engine3d.js` | `Engine3D.build(nCyl, layoutId, inductionCfg)` orchestrates: layout class → banks (groups rotated about X; crank axis = X, front = +X) → `lay.buildCylinder()` per cylinder → layout hooks (case, crank, intake, front, rear) → induction parts → `lay.buildExhaust()` → pose (`animate` at crank 0) → `lay.finish()` → grounding/framing. The flame light takes its colour from `type.glow.color`. Kinematics in `update`: `cyc = (crank − c.phase) mod c.period (720, rotary 360)`, normalised to 0..720 for the glow, then `lay.animate()`; firings and exhaust pulses are counted on the unwrapped `crankTotal` (every crossing, up to 3 per frame), so a big frame step (low fps, high rpm, the rotary's 360 period) can't skip or strobe them; slider-crank with bore offset `c.zo` (W rows) and rod length `c.rodL` (radial `lift`), or the rotor motion. Everything that turns with the crank is in `spinners` (`spin(obj, ratio, off, pitch)` returns the record; accumulated angle, so ratios ≠ 1 don't jump at the 720° wrap; `pitch` = blade/spoke spacing in degrees for parts *not* tied to the crank: the step per frame is capped at 0.4 pitch so they never strobe, and `s.over` = the real step in pitches, for blur. Used by the jet spool, the radial prop hub (120) and the steam governor (180); flywheel, pulleys and blower rotors are crank-linked, so no cap); turbo wheels are in `compressors` (spun by boost, step capped at 0.4 of their 45° blade pitch), BOV puff origins in `bovs`. `GEO` exports the constants/`firingOrder` to the other files. Each cylinder object carries `moving` (the parts shown only in cutaway: piston+rod from `_cylinder`, the throw added by `buildCrank`, the rotor for the rotary); `_applyCutaway` just toggles those. Shared helpers: `_roundBox`, `_alongX(geo, depth, xFront)` (a shape extrusion along engine X, shape x → +z), `_edges` (caches the EdgesGeometry per source geometry). Camera is fixed at three-quarter (`camDir`), fitted to the bounding box, image shifted with `setViewOffset`; then pushed back until no probe point lands on the dash: `Dash.keepOut()` reports what the cluster covers (CSS px circles/rects: tach, TEMP/BOOST, shift-light bar, key + labels and pedal when shown, lamps, odometer, radio), `main.js` hands it over with `eng3d.setKeepOut()` after every dash resize/set (reframes only on change); `_fitPts` = 26 points per mesh bbox (corners, edge and face centres) at rest, cached at build; `_clear()` tests them (every point on screen, and off the dash with a +1.2 % w margin; the on-screen test was added for the rocket's 30-engine stand, it changes nothing for the older engines), `_frame()` grows `dist` ×1.25 until clear and bisects 12 steps (a linear k under-corrects: near parts shrink slower). Works in portrait too. Before the first `setKeepOut` it falls back to `FIT_RIGHT` (NDC). A single NDC x threshold was wrong: the dash's left edge depends on height, aspect and the radio (W32/I32/Boxer32 reached under the gauges, a stricter per-layout value made the jet tiny). `lay.framePad` adds margin (radial). `_sway()` = torque roll + RPM-dependent vibration, rotating about the engine's own axis (as on mounts; the user rejected pivoting on the lowest corner). `_footPoints()` at build keeps the lowest vertex per 32×32 (x, z) cell (engine-local; meshes whose bottom is in the upper half are skipped). The mount height `mountY` follows (τ 0.12 s) `_mountTarget()`: the clearance for the *envelope* of the current rocking (lean, `vibA`, kick, `rock`, idle/cranking terms; not capped: a cap at sway 150% made sway 250% run on the corner-pivot `lift` most of the time), so a still engine sits on the floor at `baseY` and a running one rises only as much as it rocks. A swing past that (random stall jolts) gets an instant `lift` that settles back over 0.4 s. `lift`/`mountY` are in the non-finite reset in `update()`; after it `lay.afterSway()` (piston: world-space `tipW/dirW` of the stack tips, particles/jets use only those; steam/marine: a shudder added to `eng.position`). **Beat spring** `_jolt()`: `e.jolt`, a damped ~4.5 Hz oscillator kicked by every rise of `sim.kick` (dk/500, max 3, clamp ±2.5), the sway setting already in it; for engines that don't rock on mounts (jet, steam, electric, marine, rocket read it in their effects). Beat roll uses `lay.beatK` (default `swayK`). Per frame the core calls, per cylinder, `lay.animate`, `lay.cylinderFx(c, glow, sim)` (the combustion glow envelope) and `lay.exhaustPulse(c, sim)` per counted opening; `lay.onEvent(ev, sim)` for every sim event; `lay.updateFx(dt, sim, q)` (must advance `e.time`); `lay.glowPoint()` (flame light + background glow; null = none), `lay.frameBox(box)`; `lay.animK` scales the visual shaft speed, `lay.swayK`/`lay.smooth` the vibration and the lumpy idle. Generic particle helpers stay here (`_spark(c, k)`, `_flameP`, `_smoke(tip, dir, n, kind)`), and the material palette (`block` ghosts in cutaway, `cover` = accent, `brass`, `fire`, `turbo`, `turboHot`, `header`/`soot` heated from `heat`). `Engine3D.FX = EngineFX`; smoke pool 800, flames 900. |

## Wallpaper Engine specifics (verified against docs.wallpaperengine.io)
- `window.wallpaperRegisterAudioListener(cb)`: 128 values (0–63 left, 64–127 right, bass→treble), ~30 Hz, usually 0..1 (occasionally >1). Register **at the end of body**, not in `onload`. `project.json` must have `general.supportsaudioprocessing: true`.
- **WE provides no BPM.** It is computed in `audio.js`.
- Properties: only changed keys arrive; always check `p.key !== undefined`. Color is the string `"r g b"` in 0..1. File path: prefix with `file:///`.
- Media integration: `wallpaperRegisterMediaStatusListener / PropertiesListener / PlaybackListener`, registered synchronously next to the audio listener. The user enables it in WE settings. Playback states come from `window.wallpaperMediaIntegration.PLAYBACK_*` (fallback 1 = playing, 2 = paused; not verified in real WE).
- **No API to write properties or files:** the only persistent store is `localStorage` in WE's CEF. It is per monitor (each monitor has its own cache, so its own odometer), wiped in screensaver mode, and may be lost when WE resets its Chromium cache (reported on the Steam forums, not in the docs). file:// pages share one origin, so keys carry the `music-engine.` prefix; every access is in try/catch.
- Radio default: off everywhere (`project.json` `showradio: false`, `S.showRadio = false`); `?showradio=true` or the dev panel checkbox for tests.
- `cylinders` used to be a combo of strings, now it is an editable slider 1–32 (a number); `main.js` accepts both and clamps. The `turbos` key is kept (now "Forced induction") so saved `0/1/2/4` still work.
- Not verified in real WE: the `condition` syntax on properties (`"background.value == 'custom'"`), the exact name of the "allow mouse input" setting, and whether the editable `cylinders` slider can deliver non-integers (the code rounds anyway).

## Pitfalls already found (don't repeat)
- **Three.js r149 UMD (`build/three.min.js`)** on purpose: WE/`file://` doesn't like ES modules; newer versions have no UMD build. Don't pull from a CDN: the wallpaper must work offline, and jsdelivr/unpkg are blocked in the sandbox (use `npm pack three@0.149.0`).
- **Additive blending on a transparent canvas** (`alpha: true`): plain `AdditiveBlending` writes alpha=1 and paints black rectangles. Use `addBlend()` (CustomBlending: RGB One/One, alpha Zero/One) and output premultiplied color with `a = 0`.
- **`setViewOffset`**: the vertical FOV spans `fullH`, so in the fit `dist` is **multiplied** by `fullH / h`.
- `silentTime` must not be accumulated from a clamped `dt`: at low FPS the stall never triggered.
- Flame particles/jets spawn from `tipW/dirW` (world space after sway), not from `tip + eng.position`.
- The plate font size is one value for all lamps, computed from the base `fs0` (not reduced cumulatively).
- **Page hang ("Page Unresponsive" in WE):** in `_estimateTempo` the parabolic peak refinement was unclamped; `best` maximizes the prior-weighted score, not `ac`, so it can sit on a slope and the shift made the lag negative → negative BPM → `while (bpm < 80) bpm *= 2` never ended. Refine only at a real local max, clamp the shift to ±0.5 lag, reject non-positive/non-finite BPM, and keep the octave folding bounded.
- **Redline from an editable slider can be anything** (typing 7 rounded to 0): `rpm / redline` became NaN, the NaN stuck in the `_sway` phases/`heat` and the engine vanished for good. `main.js` clamps redline to 500–15000; `sim`/`engine3d` also guard the divisor, and `Engine3D.update` resets non-finite accumulators. Flames and backfire pops need `rpm > FIRE_RPM` (2500) regardless of redline.
- **Engine sinking through the floor:** `_sway` rotates the block about its origin, so under load/vibration the lowest side parts (headers, sump corners) dipped 6–14 cm under the ground plane (the shadow plane writes depth, so they looked cut off). Don't ground only at build time. Also don't clamp the lowest point to the floor every frame: that moves the visible pivot to the bottom corner and looks wrong. Use the envelope-based mount clearance (`mountY`) + the rare `lift`; a fixed clearance per sway value made the stopped engine hover over its contact shadow.
- **One rAF chain only:** `setPaused(false)` used to call `requestAnimationFrame(loop)` unconditionally; WE unpausing without a pause (or pause+unpause within one frame) stacked extra loops, each running a full frame. Use `startLoop()` (tracks `rafId`).

- **Phone rotation (landscape → portrait) left the page zoomed out** with the bg/GL canvases in the top-left corner: `Dash.resize` set the dash canvas's CSS size in px from `innerWidth/innerHeight`; after rotating back that canvas was wider than the viewport, mobile Chrome zoomed out to fit it, and `innerWidth/innerHeight` (which follow the zoom) then reported the zoomed-out size, so it stuck. Canvases are sized by CSS 100% only, and `main.js` measures `documentElement.clientWidth/Height` (`viewSize()`), plus a delayed resize on `orientationchange`. Test: `test/e2e/orientation.test.js` (Playwright `isMobile`).
- **Media listener registration must not break `if (IS_WE) … else setupDev()`**: a loop inserted between them once captured the `else`, so setupDev() ran 3× (three DemoSource feeds at ~90 Hz, BPM garbage). Keep the `for` loop after the if/else, with braces.
- **Ground the engine in its posed state:** until the first `animate()` the moving parts sit at their origins; the steam engine's rods hung below the floor there, so `build()` grounded it on them and it floated ~0.8 above its shadow after one frame. `build()` now resets the crank to 0 and calls `lay.animate(c, _cyc(c, 0), 0)` for every cylinder before `lay.finish()` and the grounding: a fixed pose, so foot points, fit points and the radial stand don't depend on where the previous engine's crank stopped (`_cyc(c, crank)` is the one cycle mapping, also used by `update()`).
- **Radial firing across rows:** `phase = tilt + row·360/rows + 360·(k%2)` with a fixed `row·180/per` stagger was even within a row, but rows landed on each other (14 = 2×7 fired in pairs) or left uneven gaps (27, 28); 3–4 rows also sat with a barrel straight behind another. A cylinder's TDC is at crank ≡ tilt + pin (mod 360), so a row of odd `per` fires every 2u (u = 360/per) from `stagger + pin + flip·u`. `rowFire(r)` keeps the pins balanced (`r·360/rows`, one throw per row) and solves `stagger`/`flip` so that value ≡ `r·2u/rows` (mod 2u): x = mod(r·(2 − per)/rows, 2), flip = x ≥ 1, stagger = (x − flip)·u. Two rows keep the half-cylinder stagger (only 2×7 flips); 3–4 rows land on distinct u/rows offsets (gcd(per − 2, rows) = 1 for every `split`). `test/scene/kinematics.test.js` checks 720/n for 14/18/27/28, the shared pin and rod/TDC.
- **Camera fit only checked the dash, not the screen edges:** the rocket's 30-engine stand (wide and deep towards the camera) had its near corner below the frame. `_clear()` now also requires every fit point on screen; the older engines didn't change (baseline).
- **File pickers asked for the microphone on Android:** `accept="audio/*"` makes Chrome offer recording (and `image/*` the camera), so it asks for the permission before the picker opens. Both pickers list extensions only (`test/e2e/panel.test.js` checks).
- **Overlapping additive plumes add up:** 9–12 rocket plumes turned into a white wall; each is dimmed by `1/√(1 + 0.15(n−1))`.
- **Never `git add -A` after downloading tools into the repo root** (`pip download` once committed 49 MB of wheels). `.gitignore` covers `*.whl` and `node_modules/`; `npm install` for the tests puts ~10 MB there, keep it out of Workshop uploads.
