Context for Claude Code / Claude when working on this project.

## What it is
An audio-reactive web wallpaper for Wallpaper Engine (WE). A 3D engine (Three.js) on the left, a 2D dashboard on the right.
The engine revs with the music (BPM + loudness), shoots flames on peaks, sways/vibrates more with RPM, and stalls after silence.
The dashboard has a tachometer with shift lights, temp and boost gauges, 8 lamps (round lamp + metal plate with screws), an ignition key, a throttle pedal, an odometer (ODO + TRIP drums), and a car radio (now playing via WE media integration).

## Architecture (plain scripts, no build step, no ES modules)
Load order in `index.html`: `three.min.js → audio.js → sim.js → engine3d.js → layouts.js → induction.js → dash.js → bg.js → media.js → odometer.js → main.js`.
Each file is an IIFE exporting a class to `window`.

| File | Responsibility |
|---|---|
| `js/audio.js` | `AudioAnalyzer.push(arr128, t)`: mono bands, spectral flux, beats (adaptive threshold), BPM (autocorrelation over ~300 frames + log-gaussian prior at 120 + parabolic interpolation, folded into 80–170), `intensity`/`power` (absolute via slow AGC + relative to 20 s EMA + beat density), `silentTime`. `tick(t)` treats "no callbacks" as silence (`silentTime = t - lastPush`). Also `DemoSource` (synthetic track with sections and a pause) and `WebAudioSource` (mic/file → 64 log bands). |
| `js/sim.js` | `EngineSim.update(dt, audio, t)`. States: `off → lamptest → cranking → running ⇄ stalling → stalled`. Fields: `rpm, throttle, boost, temp, flame, kick, pedal, ignition, pedalIn, warn{}`, event queue `takeEvents()` (`backfire`, `bov`, `smoke`, `start`). `pw = max(audio.power, pedal*0.95)` drives flames and temperature. Boost = max over source classes picked from `settings.turbos/blower`: `TurboBoost` (lag, needs revs, 1.6 max), `RootsBoost` (instant, grows with rpm, 1.1 max), `VacuumOnly` (no induction: −0.65…0). `bov` events only when `turbos > 0`. |
| `js/engine3d.js` | `Engine3D.build(nCyl, layoutId, inductionCfg)` orchestrates: layout class → banks (groups rotated about X; crank axis = X, front = +X) → `_cylinder()` per cylinder (liner, piston, rod, coil) → layout hooks (case, crank, intake, front, rear) → induction parts → `_stack()` per cylinder from the layout's 5-point path → `lay.finish()` → grounding/framing. Kinematics in `update`: `cyc = (crank − c.phase) mod c.period (720, rotary 360)`, normalised to 0..720 for the glow, then `lay.animate()`; firings and exhaust pulses are counted on the unwrapped `crankTotal` (every crossing, up to 3 per frame), so a big frame step (low fps, high rpm, the rotary's 360 period) can't skip or strobe them; slider-crank with bore offset `c.zo` (W rows) and rod length `c.rodL` (radial `lift`), or the rotor motion. Everything that turns with the crank is in `spinners` (`spin(obj, ratio, off)`, accumulated angle, so ratios ≠ 1 don't jump at the 720° wrap); turbo wheels are in `compressors` (spun by boost), BOV puff origins in `bovs`. `GEO` exports the constants/`firingOrder` to the other files. Each cylinder object carries `moving` (the parts shown only in cutaway: piston+rod from `_cylinder`, the throw added by `buildCrank`, the rotor for the rotary); `_applyCutaway` just toggles those. Shared helpers: `_roundBox`, `_alongX(geo, depth, xFront)` (a shape extrusion along engine X, shape x → +z), `_edges` (caches the EdgesGeometry per source geometry). Camera is fixed at three-quarter (`camDir`), fitted to the bounding box, image shifted with `setViewOffset`; then pushed back until `_extent()` (projected mesh bboxes) stays left of `FIT_RIGHT` (the old inline 8), so 32-cylinder engines stay off the dash; `lay.framePad` adds margin (radial). `_sway()` = torque roll + RPM-dependent vibration, rotating about the engine's own axis (as on mounts; the user rejected pivoting on the lowest corner). `_footPoints()` at build keeps the lowest vertex per 32×32 (x, z) cell (engine-local; meshes whose bottom is in the upper half are skipped). The mount height `mountY` follows (τ 0.12 s) `_mountTarget()`: the clearance for the *envelope* of the current rocking (lean, `vibA`, kick, `rock`, idle/cranking terms; not capped: a cap at sway 150% made sway 250% run on the corner-pivot `lift` most of the time), so a still engine sits on the floor at `baseY` and a running one rises only as much as it rocks. A swing past that (random stall jolts) gets an instant `lift` that settles back over 0.4 s. `lift`/`mountY` are in the non-finite reset in `update()`; after it, world-space `tipW/dirW` of the stack tips are computed (particles/jets use only those). `_jets()` = shader flame jets (axial billboard + scrolling fBm noise). `ParticleSystem` = fireballs/sparks (additive) and smoke (normal), sprite shape from the noise texture. |
| `js/layouts.js` | `EngineLayouts.get(id)` → class (unknown → V), `MAX_CYL = 32`. `EngineLayout` base holds the generic straight-block code; `InlineLayout`, `VLayout` (bank angle 60/72/90 from cylinders per bank), `BoxerLayout extends VLayout`, `WLayout extends VLayout` (pitch 0.64, rows `zo ±0.24`, `hw 0.78`, multiple of 4), `RadialLayout` (one bank per cylinder, `split(n)` → rows × odd per row ≤ 9, shared pin per row, `phase = tilt + pinOff + 360·(k%2)`, finned lathe barrels, rear housing, prop hub, stand in `finish()`), `RotaryLayout` (n = rotors; epitrochoid housings from `_troch()` (R 0.72, ecc 0.105) ghost in cutaway, side housings between rotors are rings so the rotors show, identical parts share one geometry (`_slab`, `_rotorGeo`), rotor centre `ecc·(cos θ, sin θ)` in (y, z) turned by θ/3, `period: 360` so each rotor fires once per shaft turn, `ROTOR_TDC = 270`: cycle start = a face at TDC on the plug side (−z); intake and exhaust ports on +z, two plugs on −z, all seated with `surfZ(y, side)`; turbos with `along: false` so the second column goes outward, clear of the stacks; an alternator behind the accessory pulley, accent colour on the plenum). Statics: `id`, `normCyl(n)`, `label(n)`, `turbos`/`blower` (what it can carry; radial: neither, so it is always naturally aspirated and the `turbos` property has `condition: layout.value != 'radial'`). Base helpers `_mainShaft(len, x)`, `_throw(x)`. Hooks: `banks, dims, cylinders, zOffset, buildBank, buildCylinder (default `e._cylinder`), animate(c, cyc, crank) (default slider-crank), runnerPath, plenumMat, buildCase, buildCrank, buildIntake (sets e.tbPos), buildFront (sets crankPulley), buildRear, stackPath, finish, plenum, turboMount, blowerMount, topY`. **Adding a layout** = a subclass + an entry in `LAYOUTS` + the `layout` combo in `project.json` + the dev panel option. |
| `js/induction.js` | `Induction.OPTIONS` (the `turbos` combo values `0/1/2/4/sc/sc2` → `{turbos, blower}`), `parse(v)` (unknown → `'1'`), `effective(cfg, L)` (drops turbos/blower the layout can't carry), `supported(L)`, `suffix(cfg)` (dash label), `parts(cfg)` → part instances (optional `update(dt, sim)` is called every frame by `Engine3D.update`) built in order: `RootsBlower` (on `blowerMount()`, belt tangents from `crankPulley`, 3-lobe rotors in `spinners`, case `M.blowerCase` ghosts in cutaway; on top either the butterfly injector hat (`_scoop`: stadium mouth scaled with the blower length, 3 butterflies in `M.cover` + linkage lever in `flaps`, opened in `update()` from `sim.throttle`, i.e. pedal or music load) or, when twincharged, a closed hat that becomes `e.tbPos`), `TurboSet(n)` (on `turboMount()`: `{s, tx, tz, gap, sides, along, maxTop?}`, `along` = second column along the block, else outward; `maxTop` lowers the set so the top row stays under it (inline: below the exhaust ports); size `s = turboScale(n)` in layouts.js = 1.25 + n/48 capped at 1.6, nearly constant because the block's height/width don't depend on n; charge pipes to `e.tbPos`), `AirFilter`. |
| `js/dash.js` | `Dash.draw(sim, audio, dt, t, media, odo)`. Static layer (bezels, scales, plates, screws, key/pedal mounts, odometer windows) in an offscreen canvas, rebuilt in `_static()` on resize/setting changes. `hitTest(x, y)` → `'odo' \| 'key' \| 'pedal' \| null` (`'odo'` is checked before the `showControls` early return, so TRIP can be reset with the key/pedal hidden). Odometer (`odoUnits` `km/mi/off`): `_odoStatic` places `odoR` (6 digits + tenths) and `tripR` (4 + tenths, `TRIP` prefix) between TEMP and BOOST (`cy + 1.17R` / `1.375R`, above the lamps at `1.58R`, all R-relative, so it follows the radio's rescale); `_drums` draws rolling drums: drum i rolls only while every lower drum goes 9 → 0 (`max(0, v mod 10^i − (10^i − 1))`), tenths drum dark red, no glow, visible with the ignition off. Car radio (`showRadio`): `_radioStatic` (faceplate, knurled volume knob, VFD glass with dot matrix) and `_radioDraw` (VU LED ring around the decorative knob, ▶/❚❚/■, marquee `ARTIST — TITLE`, `TRK nn`, clock; `AUX` + mini spectrum without track info; dark when ignition is off). With the radio on, the cluster gets smaller and higher (landscape `R` ≤ 0.232h, `cy` 0.385h → 0.35h; portrait `R` ≤ 0.13h, `cy` 0.64h → 0.615h) so the radio's bottom edge is at about 0.94h, clear of the Windows taskbar (WE exposes nothing about the taskbar; `screen.avail*` isn't reliable there). If it would still go below 0.955h, `radio = null`. The text does not blink on pause (the user found it distracting): ❚❚ plus a stopped marquee. A scrolling line is drawn into an offscreen strip (`_mq`) and faded at both ends with `destination-in`, because a hard clip cut the glow off. |
| `js/media.js` | `MediaInfo`: WE media integration (`onStatus/onProps/onPlayback`) → `available, title, artist, state ('playing'\|'paused'\|'stopped'), trackNo, changeT`. A new track = a new title, or a different non-empty artist (WE resends duplicates and may fill the artist in later). An empty title clears the track (back to AUX); `active(t)` also drops back to AUX 10 s after STOPPED. `state === null` (no playback event yet) is treated as playing. `fromFile(name, el)`: in the browser the radio shows the audio file picked in the settings panel (`Artist - Title.ext` split on ` - `), play/pause from that `<audio>` element (listeners ignore a replaced element); Stop / Demo / Mic → `clear()` → AUX. No hardcoded demo tracks (the user asked to remove them). `mock()/mockState()` are for tests only. Display only: it does not drive the engine (the user explicitly declined gears / pause→stall). |
| `js/bg.js` | Background presets (garage, carbon = fine 2x2 twill tile, gradient; unknown values fall back to garage) + user image (cover) + dimming. |
| `js/odometer.js` | `Odometer`: `km`, `trip` (always km; `value(units, trip)` converts to miles). `update(dt, sim, now)` (dt = the real frame step capped at 1 s, not the sim's 0.1 s clamp, so low FPS caps don't under-count) adds `rpm × 30 km/h per 1000 rpm × dt` only in `running`/`stalling` (the user chose "speed ∝ rpm", so idle ≈ 25 km/h also counts); ODO wraps at 1e6, TRIP at 1e4. Kept in `localStorage['music-engine.odometer']` in the browser **and** WE (separate from the settings, so "Reset settings" keeps the mileage): saved every 10 s while it moves, and `flush()` on `setPaused(true)`, `visibilitychange` hidden and `pagehide`. Junk/negative stored values load as 0. Several writers can share the store (two tabs), so `save()` re-reads the stored totals and adds only the distance since the last save (`dKm`/`dTrip`); resets write straight to the store. |
| `js/main.js` | `window.wallpaperPropertyListener` (applyUserProperties / applyGeneralProperties(fps) / setPaused), audio listener registration, mouse/touch/keyboard input, main loop, dev panel, URL parameters, `window.__dbg`. Browser only: the panel's choices are kept in `localStorage['music-engine.settings']` (try/catch; not the custom image blob, not `background: custom`) and applied on start before the URL parameters, which still win (URL values are never saved). The key click / `I` toggle is saved as `ignition` too (browser only). The panel is generated by `buildPanel()` from the `PANEL` table (every WE property except `schemecolor`, grouped Engine / Behaviour / Dash / Background); values are raw WE values (%, `"r g b"`), so it goes through `applyUserProperties` like WE does. `raw` keeps the last raw value per key; `syncPanel(skip)` fills the controls with the *applied* values (clamped cylinders/redline, the fallback for junk select values) and runs after every panel edit, skipping the range/colour being dragged. Mouse/touch on `#devpanel`/`#dv-show` never reach `press()` (panel controls can lie over the key). **Adding a property** = `project.json` + `applyUserProperties` + a `PANEL` row. Buttons: Reset trip / Reset ODO (confirm) / Reset settings (clears `STORE`, reloads). |

## Wallpaper Engine specifics (verified against docs.wallpaperengine.io)
- `window.wallpaperRegisterAudioListener(cb)`: 128 values (0–63 left, 64–127 right, bass→treble), ~30 Hz, usually 0..1 (occasionally >1). Register **at the end of body**, not in `onload`. `project.json` must have `general.supportsaudioprocessing: true`.
- **WE provides no BPM.** It is computed in `audio.js`.
- Properties: only changed keys arrive; always check `p.key !== undefined`. Color is the string `"r g b"` in 0..1. File path: prefix with `file:///`.
- Media integration: `wallpaperRegisterMediaStatusListener / PropertiesListener / PlaybackListener`, registered synchronously next to the audio listener. The user enables it in WE settings. Playback states come from `window.wallpaperMediaIntegration.PLAYBACK_*` (fallback 1 = playing, 2 = paused; not verified in real WE).
- **No API to write properties or files:** the only persistent store is `localStorage` in WE's CEF. It is per monitor (each monitor has its own cache, so its own odometer), wiped in screensaver mode, and may be lost when WE resets its Chromium cache (reported on the Steam forums, not in the docs). file:// pages share one origin, so keys carry the `music-engine.` prefix; every access is in try/catch.
- Radio default: off everywhere (`project.json` `showradio: false`, `S.showRadio = false`); `?showradio=true` or the dev panel checkbox for tests.
- `cylinders` used to be a combo of strings, now it is an editable slider 1–32 (a number); `main.js` accepts both and clamps. The `turbos` key is kept (now "Forced induction") so saved `0/1/2/4` still work.
- Not verified in real WE: the `condition` syntax on properties (`"background.value == 'custom'"`), the exact name of the "allow mouse input" setting, and whether the editable `cylinders` slider can deliver non-integers (the code rounds anyway).

## Pitfalls already found (don't repeat)
- **Three.js r149 UMD (`build/three.min.js`)** on purpose: WE/`file://` doesn't like ES modules; newer versions have no UMD build. Don't pull from a CDN: the wallpaper must work offline, and jsdelivr/unpkg are blocked in the sandbox (use `npm pack three@0.149.0`).
- **Additive blending on a transparent canvas** (`alpha: true`): plain `AdditiveBlending` writes alpha=1 and paints black rectangles. Use `addBlend()` (CustomBlending: RGB One/One, alpha Zero/One) and output premultiplied color with `a = 0`.
- **`setViewOffset`**: the vertical FOV spans `fullH`, so in the fit `dist` is **multiplied** by `fullH / h`.
- `silentTime` must not be accumulated from a clamped `dt`: at low FPS the stall never triggered.
- Flame particles/jets spawn from `tipW/dirW` (world space after sway), not from `tip + eng.position`.
- The plate font size is one value for all lamps, computed from the base `fs0` (not reduced cumulatively).
- **Page hang ("Page Unresponsive" in WE):** in `_estimateTempo` the parabolic peak refinement was unclamped; `best` maximizes the prior-weighted score, not `ac`, so it can sit on a slope and the shift made the lag negative → negative BPM → `while (bpm < 80) bpm *= 2` never ended. Refine only at a real local max, clamp the shift to ±0.5 lag, reject non-positive/non-finite BPM, and keep the octave folding bounded.
- **Redline from an editable slider can be anything** (typing 7 rounded to 0): `rpm / redline` became NaN, the NaN stuck in the `_sway` phases/`heat` and the engine vanished for good. `main.js` clamps redline to 500–15000; `sim`/`engine3d` also guard the divisor, and `Engine3D.update` resets non-finite accumulators. Flames and backfire pops need `rpm > FIRE_RPM` (2500) regardless of redline.
- **Engine sinking through the floor:** `_sway` rotates the block about its origin, so under load/vibration the lowest side parts (headers, sump corners) dipped 6–14 cm under the ground plane (the shadow plane writes depth, so they looked cut off). Don't ground only at build time. Also don't clamp the lowest point to the floor every frame: that moves the visible pivot to the bottom corner and looks wrong. Use the envelope-based mount clearance (`mountY`) + the rare `lift`; a fixed clearance per sway value made the stopped engine hover over its contact shadow.
- **One rAF chain only:** `setPaused(false)` used to call `requestAnimationFrame(loop)` unconditionally; WE unpausing without a pause (or pause+unpause within one frame) stacked extra loops, each running a full frame. Use `startLoop()` (tracks `rafId`).

- **Media listener registration must not break `if (IS_WE) … else setupDev()`**: a loop inserted between them once captured the `else`, so setupDev() ran 3× (three DemoSource feeds at ~90 Hz, BPM garbage). Keep the `for` loop after the if/else, with braces.
- **Never `git add -A` after downloading tools into the repo root** (`pip download` once committed 49 MB of wheels). `.gitignore` covers `*.whl`.

## Testing
Headless Chromium + SwiftShader (the sandbox has Playwright, browsers in `/opt/pw-browsers`):
```python
b = await p.chromium.launch(args=["--use-gl=angle","--use-angle=swiftshader","--enable-unsafe-swiftshader"])
await pg.goto("file:///…/music-engine/index.html?demo=1&layout=v&cylinders=8&debug=true")
await pg.evaluate("document.getElementById('devpanel').style.display='none'")
state = await pg.evaluate("__dbg.sim.state")   # __dbg = {audio, sim, eng3d, dash, S}
```
- In headless mode FPS is low and `dt` is clamped to 0.1, so sim time lags wall time. Pick frames by state (for example `__dbg.sim.flame > 0.5`), not by timer.
- Key/pedal: take coordinates from `__dbg.dash.keyC` / `__dbg.dash.pedalR` and use `page.mouse`.
- URL parameters are passed straight into `applyUserProperties` (`?ignition=false&background=carbon…`).
- **Refactor regression:** `?ignition=false` with the `bg` and `dash` canvases hidden gives a deterministic engine frame (only turbo wheels move, they spin from boost even when off); diff against screenshots from before the change.
- Before finishing, check JS syntax: `node -e "new Function(fs.readFileSync(f,'utf8'))"`, and that there are no `pageerror`s.
